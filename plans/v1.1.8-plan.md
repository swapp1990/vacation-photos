# v1.1.8 Release Plan

**Status:** PLANNED
**Branch:** `build/1.1.8` (from `build/1.1.7`)
**Date:** 2026-02-19
**North Star:** 100 downloads/month (currently ~26)

---

## 1. Problem Statement

Vacation Photos has a healthy 4.8% impression-to-download conversion rate, but only 21 impressions/day — well below the 69/day needed to hit 100 downloads/month. The app also has just 1 rating, 4 screenshots, underutilized keyword space (79/100 chars), and zero analytics. v1.1.8 bundles ASO improvements (keywords, subtitle, screenshots, What's New) with in-app review prompting and analytics to drive impressions, improve conversion, and enable data-driven iteration.

## 2. Solution Overview

Ship a single version update that addresses six P1 requirements: expand keyword coverage to 100 characters, optimize the subtitle for search ranking, add in-app review prompts after positive moments, generate 4-6 additional App Store screenshots, update the What's New text, and integrate SwapAnalytics for event tracking. Together these changes target a 2-3x increase in search impressions and a path from 1 to 10+ ratings within 60 days.

| Metric | Target | How to Measure |

| Keyword utilization | 100/100 characters | App Store Connect metadata |

## 4. Scope

### P0 — Must Ship in v1.1.8

- Proposed: `vacation,photos,travel,trips,memories,photo organizer,travel photos,holiday,gallery,album,automatic`

**REQ-04: Subtitle Optimization**
- Change subtitle from "Find your travel memories" to "Auto-organize trips & share albums"
- New subtitle adds indexed keywords: organize, trips, share, albums
- File to modify: `app.json` — add/update subtitle in expo iOS config, or update via App Store Connect metadata
- Test: Subtitle renders correctly in App Store Connect preview, under 30-character limit

**REQ-05: In-App Review Prompt**
- Install `expo-store-review` package
- Track "positive moments" counter in AsyncStorage (trip viewed, vacation shared)
- Trigger review prompt on 2nd positive moment
- Record prompt timestamp, don't re-prompt for 90 days
- Files to create/modify:
  - `package.json` — add `expo-store-review` dependency
  - `src/utils/reviewPrompt.js` — new file: logic for tracking positive moments, cooldown, and triggering review
  - `App.js` — call review check after trip view and share completion
- Test:
  - Review prompt does NOT appear on first launch or during onboarding
  - Review prompt appears after 2nd positive moment (trip viewed or vacation shared)
  - After prompt shown, it does not appear again within 90 days
  - `expo-store-review` `isAvailableAsync()` check before calling `requestReview()`

**REQ-06: Add 4-6 More Screenshots**

- New screenshots to cover:
  1. Before/after: messy camera roll → organized trips (transformation story)
  2. Year-over-year view showing multiple years of trips
  3. Share flow: selecting contact → link sent → recipient viewing
  4. Location detail: map view or distance badges
  5. Privacy angle: "Everything stays on your phone" message
  6. Stats/count: "X trips, Y photos found" summary view
- Use existing `ScreenshotMode.js` and `scripts/` tooling to generate new screenshots
- Files to modify:

  - `screenshots/` — output directory for new 6.7" and 6.5" screenshots
- Test:
  - Total screenshots ≥ 8
  - All screenshots are 1290×2796 (6.7") and 1242×2688 (6.5")
  - Each screenshot has a clear text overlay describing the feature
  - No placeholder or broken images

**REQ-07: Update What's New Text**
- Replace "Minor UI bugs fixed" with feature-rich text
- Proposed: "Now with shared vacation viewing! Receive trip albums from friends and family — tap a link to see their photos instantly. Plus: swipeable full-screen photo viewer and improved trip organization."
- File to modify: App Store Connect metadata (entered during version submission)
- Test: What's New text is set in App Store Connect before submission

**REQ-09: Integrate SwapAnalytics**
- Copy `telemetry-client.js` from LMWFY: `/Users/swapnilsawant/projects/ios_projects/lmwfy-ios/src/utils/telemetry-client.js`
- Create app-specific analytics wrapper
- Initialize at app startup with appId `vacationphotos`
- Define and track Vacation Photos events:
  - `app_opened`, `onboarding_completed`, `vp_trip_viewed`, `vp_vacation_shared`, `vp_photo_saved`, `vp_share_received`, `vp_review_prompted`
- North Star event: `trackNorthStar()` on share created
- Files to create/modify:
  - `src/utils/telemetry-client.js` — copied from LMWFY (224 lines, drop-in SDK)
  - `src/utils/analytics.js` — new file: re-exports `initAnalytics`, `track`, `trackNorthStar`; defines Vacation Photos `Events` constants
  - `App.js` — call `initAnalytics('vacationphotos')` at startup, add `track()` calls at key moments
- Test:
  - `initAnalytics('vacationphotos')` called on app startup (no crash in dev or production)
  - Events POST to `https://analytics.swapp1990.org/api/events` with correct `appId` and `eventName`
  - `track(Events.APP_OPENED)` fires on launch
  - `track(Events.TRIP_VIEWED)` fires when viewing a trip
  - Analytics is fire-and-forget — failure does not crash or block the app

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `expo-store-review` not compatible with Expo SDK 54 | High — blocks REQ-05 | Check compatibility before installing; fallback to native `SKStoreReviewController` via expo modules if needed |
| ScreenshotMode mock data doesn't cover new scenes | Medium — delays REQ-06 | Add mock data incrementally; 4 new screenshots minimum is acceptable |
| Analytics endpoint down during testing | Low — doesn't block release | telemetry-client already has timeout + retry + fire-and-forget; test with `curl` separately |
| Keyword changes don't fit in 100 chars | Low | Pre-validate character count; drop lowest-priority keyword if over |
