# v1.1.8 Release Plan

**Status:** PLANNED
**Branch:** `build/1.1.8` (from `build/1.1.7`)
**Date:** 2026-02-19
**North Star:** 100 downloads/month (currently ~26)

---

## 1. Problem Statement

Vacation Photos has a healthy 4.8% impression-to-download conversion rate, but only 21 impressions/day — well below the 69/day needed to hit 100 downloads/month. The app also has just 1 rating, 4 screenshots, underutilized keyword space (79/100 chars), and zero analytics. v1.1.8 bundles ASO improvements (keywords, subtitle, screenshots, What's New) with in-app review prompting and analytics to drive impressions, improve conversion, and enable data-driven iteration.

## 2. Solution Overview

Ship a single version update that addresses six P1 requirements: expand keyword coverage to 100 characters, optimize the subtitle for search ranking, add in-app review prompts after positive moments, generate 4-6 additional App Store screenshots, update the What's New text, and integrate SwapAnalytics for event tracking. Together these changes target a 2-3x increase in search impressions and a path from 1 to 10+ ratings within 60 days.

**REQ-05: In-App Review Prompt**
- Install `expo-store-review` package

- Files to create/modify:

  - `expo-store-review` `isAvailableAsync()` check before calling `requestReview()`

**REQ-06: Add 4-6 More Screenshots (via TemplateGen)**
- Currently 4 screenshots; target 8-10
- Screenshots will be generated using **TemplateGen** (`https://templategen.swapp1990.org`) App Store Previews category
- Each screenshot = TemplateGen template (768×1376, upscaled to 1320×2868) customized with Vacation Photos branding and app screenshots

**6 screenshots needed, mapped to TemplateGen templates:**

| # | Screenshot Theme | Existing Template | Status |
|---|-----------------|-------------------|--------|
| 1 | Stats: "X trips, Y photos found" | `appstore_feature_callout` (Feature Callout) | Ready — customize with VP stats |
| 2 | Before/after: messy camera roll → organized trips | `appstore_before_after` (Before & After) | Partial fit — shows photo comparison, not dual-phone app screens. **Needs new "App Screenshot Comparison" template** |
| 3 | Share flow: select contact → link → recipient views | None | **MISSING — needs new "Multi-Step Flow" template** (2-3 small phone screens in sequence) |
| 4 | Location detail: map view or distance badges | None | **MISSING — needs new "Map / Location" template** (map background + phone overlay + location pins) |
| 5 | Privacy: "Everything stays on your phone" | None | **MISSING — needs new "Privacy / Security" template** (shield/lock icon + privacy headline + phone) |
| 6 | Year-over-year: multiple years of trips | None | **MISSING — needs new "Timeline / Grid" template** (multiple cards in a grid or vertical timeline) |

**TemplateGen gaps to fill (4 new templates needed):**

1. **App Screenshot Comparison** — Two phone mockups side-by-side showing before→after of app screens with arrow/transition indicator between them. Different from existing "Before & After" which compares photos, not phone UIs.

2. **Multi-Step Flow** — 2-3 smaller phone screens arranged horizontally showing a sequential user flow with step numbers or arrows. For "select contact → send link → recipient views" story.

3. **Map / Location** — Map background (or map-style illustration) with phone overlay showing location-based features. Location pins, distance badges. Travel/geography theme.

4. **Privacy / Security Shield** — Shield or lock icon prominently featured, privacy-focused headline, phone showing on-device data. Reassurance design ("your data stays on your phone").

**Workflow:**
1. Build the 4 missing templates on TemplateGen
2. Generate all 6 screenshots via TemplateGen using VP branding (blue gradient #4AC4F3, travel theme)
3. Customize text overlays with VP-specific headlines
4. Export at App Store dimensions and upload to App Store Connect

- Test:
  - Total screenshots ≥ 8 (4 existing + 4-6 new from TemplateGen)
  - All new screenshots exported at correct App Store dimensions
  - Each screenshot has a clear headline describing the feature
  - Screenshots tell a coherent story when viewed in sequence
  - No placeholder or broken images

## 5. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| `expo-store-review` not compatible with Expo SDK 54 | High — blocks REQ-05 | Check compatibility before installing; fallback to native `SKStoreReviewController` via expo modules if needed |
| 4 new TemplateGen templates needed before screenshots can be generated | Medium — delays REQ-06 | Build templates on TemplateGen first; Feature Callout is already usable for 1 screenshot immediately |
| Analytics endpoint down during testing | Low — doesn't block release | telemetry-client already has timeout + retry + fire-and-forget; test with `curl` separately |
| Keyword changes don't fit in 100 chars | Low | Pre-validate character count; drop lowest-priority keyword if over |
